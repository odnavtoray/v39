# Одна Друга — Beta v24: запуск

## Локальная проверка
1. Открой PowerShell в папке проекта.
2. Выполни:
   `pip install -r requirements.txt`
3. Запускай бета-сервер:
   `py serve_beta.py`
   или двойным кликом `start_beta.bat`.
4. Открой `http://127.0.0.1:8000`.

`py app.py` оставлен только для локальной разработки и по умолчанию запускается без debug.

## Что изменено для Beta v24
- production WSGI через Waitress;
- debug выключен по умолчанию;
- секретный ключ больше не захардкожен: берётся из `SECRET_KEY`, а локально создаётся постоянный ключ в `instance/.beta_secret_key`;
- CSRF-защита всех POST/PUT/PATCH/DELETE запросов;
- HttpOnly + SameSite=Lax для session cookie;
- Secure-cookie и HSTS включаются при `HTTPS_ENABLED=1`;
- security headers и базовый Content-Security-Policy;
- загрузки проверяются через Pillow как реальные изображения, нормализуются в JPEG и получают случайное серверное имя;
- ограничение общего запроса 25 МБ, одной фотографии 10 МБ, максимум 5 фото;
- `/healthz` для проверки доступности;
- резервная копия БД и фотографий через `py backup_beta.py`.

## Перед открытием сайта из интернета
- Использовать HTTPS.
- На хостинге задать `SECRET_KEY` длинной случайной строкой.
- Задать `HTTPS_ENABLED=1`.
- Не публиковать содержимое `instance/`, `backups/` и секреты.
- Настроить ежедневную резервную копию.
- Для закрытой беты можно оставить SQLite. Перед заметным ростом нагрузки перейти на управляемую PostgreSQL.
- Пользовательские фото сейчас хранятся локально; для масштабирования перенести их в объектное хранилище.

## Важно
Waitress — это WSGI-сервер приложения. На публичном домене HTTPS обычно завершается на платформе хостинга или reverse proxy.
